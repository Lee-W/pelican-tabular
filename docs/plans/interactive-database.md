後續相容性修正已納入：資料庫 UI 僅由明確的 `view` shortcode 啟用，並自動引入資源；OSM 在既有資源 URL 組裝共用核心與舊表格樣式。一般表格不載入資料庫控制項。已補齊淺色變數、Attila 控制項與配色、子站及真實部落格回歸。只升級並保留一般表格，不需修改站台設定；entertainment-blog 後續另以內容、設定與頁面樣式改動，將作品排名頁升級為新檢視。

結論：可以做，而且能沿用目前的 YAML／JSON／CSV 與 Pelican 靜態建置流程。新增可選的資料庫檢視，完整涵蓋搜尋、篩選、排序、桌面表格、手機卡片與詳情展開；作品類型、閱讀進度、評分等規則由站台設定，不寫死在通用 plugin 裡。

目標依賴方向是 **`pelican-osm → pelican-tabular`**。通用表格的 Python 渲染、JS 互動及 CSS 由 tabular 維護，OSM 經由轉接層使用；先完成這個共用基礎，再加入參考頁的功能。

使用者已確認範圍為「完整作品資料庫：互動與視覺都做」。前置階段、第一階段與第二階段都是必要交付；拆階段只代表實作順序，完成搜尋／篩選尚不算完成本計畫。

作品資料庫作為通用核心的完整範例與可套用設定交付，包含代表性資料、Pelican 頁面、樣式和操作說明。視覺借鏡參考頁的資訊層次與操作方式，配合站台 theme 設計。

**實作前的架構與改動入口**

盤點方法：從作者使用 shortcode／全域設定，以及讀者操作表格這兩類入口，追到資料載入、HTML 輸出、前端 handler 和測試；另外讀取本機 `pelican-osm` 的前端入口，確認跨 plugin 的接管行為。

| 入口／流程 | 目前位置 | 需要處理的事 |
| --- | --- | --- |
| 全域設定 | `tabular.py::_resolve_settings` | 加入具名檢視設定與驗證 |
| shortcode | `_parse_shortcode_args` → `_replace_match` | 新增 `view`、`id` 等參數，明訂優先順序 |
| 資料載入與連結 | `_load_data_file` → `_resolve_rows` | 沿用格式與連結處理，建立前端需要的公開欄位資料 |
| 排序／分組／彙總 | `_render_table_html` → `_collapse_rows` | 區分原始值、顯示值與分組；避免篩選已彙總資料造成錯誤 |
| 一般列與群組列 | `_render_table_html` 內兩條列輸出路徑 | 都要能產生相同的列識別與欄位 metadata |
| Markdown／內容生命週期 | `_process_content`、`_init`、`_process_article`、`register` | 支援同頁多表及靜態資源發佈，保留 Article／Page 入口 |
| OSM 地點列表 | `osm.py::_process_content` → `_render_place_list_html` | 將地點與 schema 設定轉成 tabular 的公開介面，保留 OSM 專屬呈現 |
| 現有前端 | 外部 `osm-map.js::initSortableTables` | 抽出排序／收合／表格篩選，由 tabular 接手，OSM 移除重複綁定 |
| OSM 樣式與資源 | `osm-map.css`、`osm.py::_copy_static`、`register` | 分離通用與地圖專屬樣式，接上共用資源發佈及載入 |
| 文件與驗證 | `README.md`、`tests/`、`pyproject.toml`、CI | 補設定範例、前端測試與套件資源驗證 |

目前本機 checkout 的兩個 `pyproject.toml` 都沒有宣告依賴對方，OSM 的 Python 程式也尚未呼叫 tabular。tabular 中部分 helper 註記為從 OSM 搬來，兩邊仍各自有表格渲染與分組邏輯。

本 repo 目前沒有自己的 JS／CSS，也沒有對應的前端測試。排序、收合由外部 `osm-map.js` 提供；表格筆數目前在 Python 建置時產生，而且放在 wrapper 外，刻意避免被 OSM 改寫。這是目前的前端耦合，並非目標套件依賴方向。

**前置階段：讓 OSM 使用 tabular 的共用表格能力**

1. 定義責任邊界及公開介面。
   - tabular 負責欄位／列模型、基本儲存格、排序、分組、彙總、表格 HTML、互動控制與通用樣式；公開介面以傳入資料與設定運作，不依賴 tabular shortcode 的初始化全域狀態。
   - OSM 保留地點檔案解析、schema 擴充欄位解讀、`items` 展開、座標／GeoJSON／Leaflet，以及地圖連結與照片燈箱；透過欄位描述、儲存格 renderer 或事件介面接入表格。
   - 表格標籤篩選可共用；地圖 marker／圖層篩選仍由 OSM 管理。通用核心不匯入 OSM，也不解讀 `x-osm-*`。

2. 先比對兩邊現有實作，再搬移可共用部分。
   - 逐項比對 `_collapse_places`／`_collapse_rows`、儲存格輸出、群組計數、空值與聚合語意；OSM 的圖片、地圖連結、schema 排序提示等差異由轉接層承接，不以 tabular 的現有功能直接覆蓋。
   - 建立穩定的 Python 渲染入口與前端初始化入口，讓 `{% table %}` 和 OSM 的列表 shortcode 呼叫同一個核心。
   - 把 `osm-map.js` 中通用排序、群組收合與表格標籤篩選搬到 tabular；保留必要的事件／callback 供 OSM 圖片功能使用。前端初始化需可重複呼叫而不重複綁定。
   - 通用 CSS 由 tabular 提供；既有 `osm-*` class、CSS 變數及錨點有已發佈消費者，透過相容輸出或別名遷移，避免直接改名破壞文章與 theme。

3. OSM 宣告依賴並完成轉接。
   - tabular 先發佈包含公開介面的版本，OSM 再宣告最低相容版本，更新 lockfile、列表轉接層與 theme 載入文件。
   - OSM 明確接用 tabular 的資源註冊介面；只啟用 OSM plugin 時也能發佈表格資源，同時啟用兩個 plugin 時只註冊一次。安裝依賴不等於已啟用其 Pelican signals。
   - OSM 刪除已搬移的通用實作，保留專屬轉接。新舊版本共存僅作遷移安排，不能成為長期兩套表格控制器。

4. 在新增互動前驗證相容性。
   - 覆蓋 tabular 單獨啟用、OSM 單獨啟用及兩者並用；確認 HTML、群組／聚合筆數、排序、標籤篩選、圖片、地圖連結與錨點的既有行為。
   - 前置階段必須保留既有彙總功能；後續「新搜尋／篩選與彙總同用」的限制不能套用到既有 OSM 列表。
   - 驗證 JS／CSS 的載入順序、重複註冊及 theme 覆寫相容性。下游實際站台的資源引入位置仍需另行盤點。

前置階段驗收：兩個 plugin 的通用表格能力只有一份實作，由 tabular 提供；tabular 可單獨運作，OSM 透過明確依賴與轉接使用，既有列表功能持續可用。

**建議介面草案**

簡單使用維持 `{% table data/books.yaml %}`。較複雜的互動設定放在 `pelicanconf.py`，shortcode 指定具名檢視，避免塞入大量參數。

```python
TABULAR_VIEWS = {
    "works": {
        "fields": ["title", "format", "genres", "creator", "rating"],
        "search_fields": ["title", "creator", "publisher", "note"],
        "display": {
            "layout": "responsive",
            "title_field": "title",
            "meta_fields": ["format", "genres", "creator", "rating"],
            "detail_fields": [
                "publisher",
                "released_at",
                "completed_at",
                "status",
                "note",
            ],
        },
        "filters": {
            "status": {
                "control": "chips",
                "match": "any",
                "options": [
                    {"value": "ongoing", "label": "正在看"},
                    {"value": "completed", "label": "已看完"},
                    {"value": "planned", "label": "想看"},
                ],
            },
            "format": {"control": "chips", "match": "any"},
            "genres": {"control": "chips", "match": "all"},
            "rating": {"control": "chips", "match": "any"},
            "released_at": {"control": "year_range"},
            "completed_at": {"control": "year_range"},
        },
        "presets": [
            {"label": "正在看", "filters": {"status": ["ongoing"]}},
            {"label": "想看", "filters": {"status": ["planned"]}},
        ],
        "query_sync": True,
    },
}
```

```text
{% table data/works.yaml view="works" id="works" sort_by="rating" sort_order="desc" %}
```

上述為原始介面草案；現行設定以 README 為準。設定優先順序為 shortcode > 具名檢視 > 現有全域預設；列表整份取代、欄位標籤按 key 合併。

未提供 `options` 時由資料推導可選值；提供時以設定控制順序及顯示名稱，資料中未列出的值應有明確警告。內部值與中文標籤分離，標籤變更不應讓既有分享網址失效。

**第一階段：可獨立運作的互動表格**

1. 建立設定與資料契約。
   - 新增具名檢視的解析、欄位驗證與錯誤訊息；不強迫改寫既有資料格式。
   - 將搜尋文字、篩選原始值、排序型別／值與顯示 HTML 分開。連結用文字搜尋；日期用 ISO 值排序；數字不能依畫面文字字典序排序。
   - YAML 日期、JSON／CSV 日期字串及數字字串需有一致規則；對無法可靠推斷的欄位提供型別設定。
   - 只序列化顯示、搜尋、篩選與排序所需的明確欄位，不把整筆輸入資料原封不動送到前端。未顯示但用於搜尋的欄位仍屬公開資料，文件需說明。

2. 在共用 HTML、JS／CSS 與資源流程上加入互動檢視。
   - 舊 shortcode 經共用核心的相容模式產生原有 markup；新檢視使用 `tabular-*` class。兩者的表格互動都由 `tabular.js` 管理，搜尋／篩選依設定啟用。
   - 已遷移的 OSM 不再自行綁定通用表格互動。對尚未升級的 OSM，新模式避免帶 `.osm-place-list`；此措施僅處理過渡版本，正式整合以相容版本組合為驗收基準。
   - 保留 build-time HTML 與正常連結；沒有 JS 時仍能閱讀完整表格。控制項在成功初始化後才啟用。
   - 使用前置階段建立的 static 發佈／註冊介面，擴充控制項樣式及 JS；每頁只引入一次。檢查 `SITEURL`、子路徑部署與本機預覽的資源 URL。
   - 新模式的表格、欄位和群組錨點都含表格 ID；同頁重複 ID 應報錯。既有模式不在此時改名，避免破壞文章連結。

3. 實作單一互動狀態與結果計算。
   - 狀態包含搜尋字串、各欄位選取值、排序欄位／方向與群組收合狀態。控制列與後續快速篩選按鈕共用這份狀態。
   - 搜尋先去除前後空白、忽略大小寫；空查詢符合全部。不同篩選欄位採 AND，同欄位依 `match` 判定；清除選取回到無搜尋／無篩選，保留排序。
   - 每次更新重算符合筆數、空結果提示及群組筆數；沒有符合資料的群組隱藏。收合只影響顯示，不改變符合筆數。
   - 分組表格維持群組順序，在群組內排序；使用同一套可見性判定處理篩選與收合，避免相互覆寫。
   - 第一階段不支援新互動檢視與 `aggregate` 同用，遇到此組合提供明確錯誤。舊靜態模式的彙總照常；未來需另設計「先篩原始列，再重新彙總」才能加入。

4. 加入網址狀態同步。
   - 預設以 `id` 作命名空間，例如 `?works.status=ongoing&works.q=動畫`，避免同頁多表互相影響。
   - 如獨立資料庫頁需要 `?status=ongoing`，提供明確選用的無前綴模式；同頁只能有一張表使用它。
   - 初始化讀取網址；操作後只更新自己的參數，保留其他 query 與 hash。值需編碼，多選以重複參數表示；未知參數／值安全忽略，不產生 HTML。
   - 第一階段採 `replaceState`，避免每個字和每次篩選都新增歷史紀錄；監聽 `popstate`，恢復瀏覽器導覽到的網址狀態。逐次篩選的上一步／下一步不是此版承諾。
   - 啟用同步時要求穩定 ID；網址缺少篩選條件就表示不限，不複製參考站預設「正在看」的作品專屬邏輯。

5. 驗證並提供可建置範例。
   - Python：設定解析、型別轉換、HTML escaping／內嵌 JSON 安全、同頁 ID、一般列與群組列、Article／Page、Markdown 路徑及舊 HTML regression。
   - 前端：搜尋與複合多選、空值、日期／數字排序、零結果、清除、網址還原、多表隔離、群組計數與收合。
   - 整合：同頁放新版互動表格、舊表格、OSM 列表與 OSM 地圖，確認表格都使用共用核心、只綁定一次且互不干擾；停用 JS 後仍可閱讀。
   - 無障礙：搜尋 label、篩選按鈕選取狀態、排序 `aria-sort`、鍵盤操作及結果筆數播報。中／英／日 UI 字串沿用 plugin 既有語言解析方式。
   - 新增前端測試流程並接入 CI；使用真實瀏覽器測試 URL、DOM 互動與共存情境。保留 `uv run poe lint`、`uv run poe cover`。
   - 以約 1,000 筆與 5,000 筆合成資料量測搜尋／篩選延遲、HTML 大小和初始化時間，再決定是否需要 debounce、分頁或其他效能策略。
   - 建置 wheel 並用最小 Pelican 範例產站，驗證安裝後仍包含且能載入 static 資源。

第一階段驗收：作者能從既有資料檔產生可搜尋、複合篩選、排序及分享狀態的表格；重新開啟網址能還原條件；同頁多表及既有 OSM 功能正常；未選用新模式的文章輸出不變。

**第二階段：完整作品資料庫的視覺與操作（必要交付）**

先為桌面、手機與空結果狀態建立版面草稿，再依序完成日期／年份區間、列詳情展開、badge 樣式、快速篩選預設與手機卡片。實作前補做參考頁的實際瀏覽器檢視，確認收合、間距及窄螢幕操作；目前公開 HTML／JS 的判讀不取代視覺驗證。

| 區域 | 必要呈現與操作 |
| --- | --- |
| 篩選區 | 可收合面板、已選條件數、清除選取；形式／進度／評分／類型以有選取狀態的按鈕呈現 |
| 搜尋與日期 | 跨欄位搜尋及清除搜尋；發行、閱畢年份起訖，手機可正常換行操作 |
| 結果工具列 | 排序方向、符合／總筆數、「正在看」「想看」快速切換；有明確資料來源時顯示最後更新日期 |
| 桌面表格 | 作品名稱、形式、類型、創作者、評分；清楚的欄位層次與詳情展開入口 |
| 手機卡片 | 名稱與評分優先，標籤與創作者接續；長標題、缺值與多標籤不破壞排版 |
| 詳情區 | 出版／製作、發行日期、閱畢日期、進度、簡評，以及已設定的心得連結 |
| 視覺狀態 | 明確的選取／焦點／展開狀態、評分說明、零結果提示、深淺色樣式 |

詳細行為如下：

- 日期區間採包含兩端；缺少日期的列在有範圍條件時不符合；多日期值需明訂採「任一日期在範圍內」。開始晚於結束時在 UI 提示並拒絕套用。
- 詳情欄位由設定指定，與顯示欄位分工；連結點擊維持導頁，不觸發整列收合。詳情 DOM 緊跟所屬資料列，排序／篩選時一起移動或隱藏。
- badge 顏色、值標籤與排序順序由作者設定，支援不同站台的評分級距；不預設參考站的星數規則。
- 快速按鈕只是套用同一組篩選狀態，不另寫一套資料過濾流程。
- 年份範圍與快速篩選也納入網址同步，分享連結須還原全部查詢條件。展開的列與篩選面板開合屬顯示狀態，初版不寫入網址。
- 桌面表格與手機卡片共用資料和篩選結果；若有兩份 DOM，使用不同元素 ID，確保隱藏版本不進入鍵盤操作順序，且詳情狀態一致。
- 新 CSS 使用有範圍的 class 與可覆寫變數，配合站台字體和深淺色。是否需要封面圖片另行決定，參考頁目前主要是文字資料卡。

第二階段驗收：相同條件在桌面與手機得到相同資料、筆數及排序，詳情操作可用鍵盤完成，並以瀏覽器實際檢查排版。至少檢查 360px、768px、1280px 寬度與深淺色，涵蓋長標題、多標籤、無評分、缺日期、展開詳情與零結果；手機使用卡片，控制項不能溢出畫面。

整體完成條件：

- 從範例資料與設定可直接建置完整作品資料庫頁，具備上表所有必要呈現及操作；資料欄位和樣式可套用到作者自己的作品清單。
- 讀者可用進度＋類型＋年份＋搜尋縮小結果、切換排序、展開詳情並開啟心得連結；分享後重新載入能還原查詢，清除後回到完整清單。
- 同一網址在桌面與手機顯示相同結果，完整完成兩種版面的瀏覽器驗證；通用核心的獨立使用及 OSM 相容性檢查也通過。
- 文件說明資料格式、評分／狀態設定、篩選語意、網址參數、theme 引入及外觀覆寫；附可重現的視覺驗證頁面或截圖。

預計新增模組可按責任拆成通用渲染核心、`views.py`／`assets.py`、`static/js/tabular.js`、`static/css/tabular.css`。模組名稱於實作時決定；抽離範圍以兩個 plugin 需要共用的責任為準。

兩站的既有頁面已用實際內容、設定與安裝的 Attila 產站驗證。未選用新檢視時保留既有表格；選用時只需新增資料／具名檢視設定及 `view` shortcode，資源由 plugin 引入。將兩站的既有作品資料整合成新資料庫頁面，仍是另一次明確的站台改版。

初版不需要 API 服務、資料庫或 React，也不涵蓋線上編輯、帳號、AniList／Notion 同步與自動補資料。它們不影響靜態資料瀏覽功能的可行性，但需要另外的需求與資料流程。

這項工作包含跨 repo 的共用核心遷移及完整作品資料庫的互動與視覺呈現。先確立 `pelican-osm → pelican-tabular` 並完成既有行為的相容驗證，再加入第一階段互動功能，最後完成第二階段的桌面／手機呈現與整體驗收。
